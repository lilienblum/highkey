# Piko

- Use Bun for JavaScript commands, including `bun run fmt`, `bun typecheck`, `bun lint`, and `bun test`. Do not use npm or Node.
- `apps/api` is the independent Rust HTTP API. `apps/dashboard` is TanStack Start on Bun and proxies /api requests. The API knows nothing about the dashboard. SQLite owns management state; each product has its own DuckDB file under data/products/, and its application logs a separate DuckDB file under data/logs/. Events and logs are separate signals with separate keys, storage, and retention. Authentication belongs to Cloudflare Access; never add a built-in login or admin token. Keep public ingestion keys. Keep blocking database work off Tokio HTTP workers.
- Keep ingestion acknowledgments after commit, bounded queues, product-scoped deduplication, and typed properties intact.
- Run `bun run fmt` (bare `bun fmt` runs Bun's built-in formatter), `bun typecheck`, `bun lint`, `bun test`, `bun run build`, `cargo test`, and `cargo clippy --all-targets --all-features -- -D warnings` for relevant changes.
- Dashboard primitives use shadcn/ui on Base UI (`@base-ui/react`), with Hugeicons and the local single-theme Kanagawa Wave styles (orange primary, yellow/violet/aqua data accents). Keep `components.json` on `base-vega`; use `render` composition, not Radix or `asChild`. Preserve keyboard/focus behavior, SSR labels, and stable refresh geometry.
- Custom dashboards are API-owned `piko.dashboard/v1` documents, written by agents over MCP, never edited by hand in the dashboard UI. `/api/read/*` is the only credential-free CORS surface (loopback plus `PIKO_CORS_ORIGINS`), and MCP lives in the API (`/api/mcp`, `/api/read/mcp`); the dashboard's `/mcp` forwards to `/api/mcp` and is the address users are shown.
- MIT license. Keep documentation and collection examples aligned with API changes.
- For dashboard UI work, read `apps/dashboard/PRODUCT.md` and `apps/dashboard/DESIGN.md`; the normative design sidecar is `apps/dashboard/.impeccable/design.json`.

- Support native Tako apps (root tako.api.toml / tako.dashboard.toml), standalone Docker Compose (docker compose up --build -d), and optional Tako Compose hosting (tako.compose.toml / compose.yaml). Run Compose through the Docker or Tako CLI directly, without Bun wrappers. Keep Tako itself unchanged. Native API post-commit webhook hints feed the dashboard ephemeral channel; never place raw events or credentials in channel messages. Compose uses the existing automatic polling without channels. Native API data belongs under TAKO_DATA_DIR; Compose mounts its named volume at /data. Exactly one API process owns each directory; keep Compose API updates stop-first and never claim overlapping API rolling updates are safe.

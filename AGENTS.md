# Piko

- Use Bun for JavaScript commands, including `bun run fmt`, `bun typecheck`, `bun lint`, and `bun test`. Do not use npm or Node.
- `apps/ingest` is the Rust ingest app: it only receives events and logs (`/api/ingest`, `/api/logs/ingest`, `/api/logs/v1/logs`) and serves `/tracker.js`. It is stateless and changes rarely, so it knows nothing about the dashboard. `apps/dashboard` is TanStack Start on Bun and owns everything else: projects, sources, keys, queries, dashboards, saved views, MCP and live hints, with management state in SQLite. Events and logs live in self-hosted ClickHouse; they are separate signals with separate keys, tables and retention. Cloudflare Access is no longer the plan: Piko is getting its own login, with organizations and users (Better Auth; design in progress). Keep public ingestion keys. Keep blocking database work off Tokio HTTP workers.
- The two apps share only ClickHouse: the dashboard owns the migrations (`clickhouse/migrations`) and mirrors keys into `piko.ingest_keys`; the ingest app checks `piko.ingest_contract` at start. Change that contract expand-then-contract: add what the new ingest app needs first, and remove what the old one used only after it is gone.
- Keep ingestion acknowledgments after commit, bounded queues, product-scoped deduplication (exact for 24 hours, the first copy wins), and typed properties intact. One ingest process per deployment, because exact dedup relies on it.
- Every project reads ClickHouse as its own user, through `SQL SECURITY DEFINER` views that hold only its rows. Dashboard documents never carry SQL: queries are events, logs, funnel or retention entities.
- Run `bun run fmt` (bare `bun fmt` runs Bun's built-in formatter), `bun typecheck`, `bun lint`, `bun run test` (bare `bun test` covers only `sdk/`; start its ClickHouse once with `bun scripts/clickhouse.ts test-up`), `bun run build`, `cargo test`, and `cargo clippy --all-targets --all-features -- -D warnings` for relevant changes. Run `bun run test:e2e` for UI changes and `bun run test:load` for ingest or storage changes.
- Dashboard primitives use shadcn/ui on Base UI (`@base-ui/react`), with Hugeicons and the local single-theme Kanagawa Wave styles (orange primary, yellow/violet/aqua data accents). Keep `components.json` on `base-vega`; use `render` composition, not Radix or `asChild`. Preserve keyboard/focus behavior, SSR labels, and stable refresh geometry.
- Custom dashboards are dashboard-owned `piko.dashboard/v1` documents, written by agents over MCP, never edited by hand in the dashboard UI. `/api/read/*` is the only credential-free CORS surface (loopback plus `PIKO_CORS_ORIGINS`), and MCP is served by the dashboard (`/api/mcp`, `/api/read/mcp`); `/mcp` is the address users are shown.
- MIT license. Keep documentation and collection examples aligned with API changes.
- For dashboard UI work, read `apps/dashboard/PRODUCT.md` and `apps/dashboard/DESIGN.md`; the normative design sidecar is `apps/dashboard/.impeccable/design.json`.

- Piko runs as two native Tako apps only (root `tako.ingest.toml` and `tako.dashboard.toml`); there is no Docker Compose or Docker image. Locally ClickHouse runs in Docker (`bun scripts/clickhouse.ts dev-up`); in production it is a ClickHouse server installed on the host with Piko's `deploy/clickhouse` settings. `bun run dev:standalone` runs the same apps without Tako. Keep Tako itself unchanged. The ingest app's post-commit webhook hints and the dashboard's own writes feed the dashboard's ephemeral channel; never place raw events or credentials in channel messages. The dashboard's `state.sqlite` lives under `TAKO_DATA_DIR`, and exactly one dashboard process owns it. The ingest app holds no state.
